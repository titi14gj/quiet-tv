# tvOS 材质重做方向

当前 4.1 不是视觉验收版本。问题在于图稿本身和焦点结构，而不只是宽高比。

## 已确认的问题

- `TvIcon` 把品牌图稿简化成手绘符号，再给所有品牌套同一种渐变，品牌比例和笔形不准确。
- 背景与标识画在同一个 Canvas 上，无法独立移动；只有整张卡片放大。
- `GlassView` 叠加半透明白色填充、亮边与外发光，导致卡片发白，取代了应有的悬浮层次。
- 电视遥控焦点需要细微的倾斜、回弹、投影变化，不能只依靠粗白边。

## 实现目标

1. 首页仍只有四个横向图标，整行靠下，中间留给壁纸；使用应用真实高清图稿，禁止继续用近似手绘品牌标识替代。
2. 每个图标分成背景、品牌前景、光泽层；背景与前景分别响应焦点。
3. 选中约放大 1.10 倍，增加柔和下投影；前景轻微抬升，光泽受移动方向影响。
4. 移除当前覆盖整张卡片的白色玻璃焦点框；轮廓仅保留极细的材质高光。
5. 方向键移动时短暂轻微倾斜并回正；不做持续摇晃。所有层在失焦后恢复。
6. 标签视觉居中；保持四卡行的基线和一致留白，不添加首页推荐海报。
7. 黑底主题色光晕保持低亮度；mac 壁纸独立保留，不混入卡片材质。
8. 保留已工作的 HDMI 端口、CEC 设备名称、直接切换，以及焦点记忆。

## 验证边界

材质图片样稿只说明外观，不证明遥控动画、性能、图标原稿准确度或电视安装效果。实施后需在 API 21 真机验证快速左右切换、图层复位、滚动展开、从应用返回、中文标签及 HDMI 选择。

参考：https://developer.apple.com/design/human-interface-guidelines/app-icons

Apple 文档描述 tvOS 分层图像、焦点抬升、表面照明和视差。Android 原生实现需自行复现这些表现，不能直接使用 tvOS 运行时效果。

## 2026-10-19 实测与布局补丁 4.2

- `wm size`、DisplayManager 和 SurfaceFlinger 均报告当前桌面 1920×1080，密度 240 dpi，桌面 buffer 也是 1920×1080。4K 面板不等于当前系统 UI 以 4K 合成。未强制修改系统分辨率。
- 当前壁纸原图：aurora 1920×1080，mac-silk 1672×941，mac-coast 1672×940，尚不是 4K 素材。不能靠放大文件宣称获得原生 4K 细节。
- 后续交付应以 3840×2160 壁纸源和矢量/足够分辨率的分层图稿为目标，抗锯齿、滤波与实际缩放效果仍须真机检查。
- 4.2 只调整四图标靠下布局与 PopupWindow 屏内限位，没有移植新材质。安装后版本已核验，截图见 backup/v42-bottom-home.png、v42-settings-safe.png。
- 设置菜单当前截图完整，右边界约 x=1836，距 1920 边缘约 84 像素。未在截图复现用户观察到的实屏裁切，不据此排除电视显示缩放问题。
